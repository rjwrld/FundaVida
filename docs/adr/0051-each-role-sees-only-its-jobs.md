# Each role sees only its own jobs, and the heavy pages become tools

_Accepted (declutter review, 2026-10-08). Extends ADR-0035; amends ADR-0023, ADR-0032, ADR-0038, ADR-0040, ADR-0046. ADR-0022 stands._

ADR-0050 made each dashboard a short worklist. The rest of the app still read as generated: a student's sidebar offered Programs, Grades, Attendance, and Certificates — four pages restating what their Course page, their dashboard, and /me already show — a teacher's offered the same four, and the TCU trainee kept a TCU page that duplicated the dashboard ADR-0050 made their home. The heavy pages were heavier still: Enrollments rendered 24 Sede → Course cards (about 9,700 px), Attendance a 1,065-row ledger, and the Course page opened with an outbox table and two cards restating its title. A reviewer gives each role a minute or so. So each role's navigation keeps only that role's real jobs, the heavy pages become the tool that job needs, and what is not essential is **deleted** — code, tests, locale keys — not moved.

## Navigation per role

Nav and routes derive from the matrix's `view` cells (ADR-0010). Reads go through scope tokens (ADR-0008), and the store never checks `view`, so emptying a role's `view` cell removes its nav item and route while every scoped read elsewhere keeps working — the ADR-0035 precedent for Programs/tcu, applied wider.

| Role    | Nav after this ADR                                                                                                                                 | `view` cells cut                           |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| Admin   | Dashboard · Calendar · Programs · Courses · Certificates · Students · Teachers · Enrollments · Grades · Attendance · TCU · Bulk Email · Audit Logs | none (Programs stays)                      |
| Teacher | Dashboard · Calendar · Courses · Students                                                                                                          | programs, grades, certificates, attendance |
| Student | Dashboard · Calendar · Courses · My profile                                                                                                        | programs, grades, certificates, attendance |
| TCU     | Dashboard · Calendar                                                                                                                               | tcu (keeps `log`)                          |

Every surviving surface reads through a scope token or an action cell, never `view`: grading is `enter`/`edit grades` (`teacherCanGrade`), marking is `mark attendance` (`courseOwned`), logging hours is `log tcu`, the roster is `view enrollments` with the Course in context, and a Course's Certificates and a Student's own records ride the `ownCourses`/`own` tokens. The programs scope tokens stay `'all'` for teacher and student (the course form and filters name Programs); only the page goes. One route moves: session marking (`courses/:courseId/sessions/:sessionDate/mark`) hung off the `attendance` view gate, so it now rides the `courses` gate — the page already checks `mark attendance` with the Course in context, the only check that resolves a teacher's `courseOwned` cell.

Sidebar group labels render only when a role has more than one group, and the first group is **Workspace**: for a teacher or student it no longer holds Programs, so "Programs" named a page the group does not contain.

## Pages

- **Student Courses is Browse.** `/app/courses` renders the browse-and-request view for the one role that requests enrollments (ADR-0016/0043); admin and teacher keep the catalog list. The student branch of the list, its Browse button, and the `/app/courses/browse` route go. Browse lists each open Course by name with "N seats left" through the seats aggregate (never raw enrollments); the Level column (always the student's own, ADR-0016), the Program column (the name leads with it), and the caption band go. Course detail from the dashboard links is unchanged.
- **/me is identity, Certificates, Guardian.** The enrollments roll-up repeated the dashboard's My courses table. Per ADR-0032 the page owns its queries and there is no `mode` prop: /me composes the shared identity and guardian panels around the certificates section, and the detail page keeps the full `StudentProgress` hub.
- **Calendar sidebar is a marker's.** Admin and teacher keep the agenda sidebar (ADR-0038/0044); a student's or TCU volunteer's canvas runs the full width. The student progress bucket, both roles' banner lines, and their agenda shapes are deleted.
- **Enrollments is the request queue** (amends ADR-0023). One flat table — Student · Course · Campus · Requested · actions — with a status filter opening on Pending (Pending / Approved / All). Pending rows are approved or rejected in place with the same rows, columns, and mutations as the dashboard queue (`useEnrollmentRequests`); approved rows of a live cohort can be unenrolled (a closed cohort is terminal, ADR-0024). The Sede → Course grouping, its 24 mini-tables, the stat tiles, and the approval sweep go: the page's job is deciding requests, and a Course's roster is on the Course.
- **TCU (admin)** renders `TcuApprovalQueue` uncapped, then the trainee roster; the activity log appears only when the roster selects a trainee — theirs, newest first, paginated, with no Trainee column. The log table is one `TcuActivityLog`, shared with the trainee's dashboard.
- **Attendance is a per-Course rollup.** One row per scoped Course that has held a Session — Course · Campus · Sessions held · Attendance (rate with a bar) · Unmarked — worst first: live unmarked work, then the lowest rate. A closed cohort's gaps are final (ADR-0024), so they show muted and never outrank work that can still be done. Each row links to the Course's Sessions section. It derives through a pure `attendanceRollup` over the existing sessions and `isSessionMarked` rule — no new data, no `STATE_KEY` bump. Courses that have held no Session yet are left out: there is nothing to roll up. Grades stays a ledger.
- **Course detail** (amends ADR-0040 and ADR-0046; ADR-0022 stands). No eyebrow; the title, one meta line (Campus · Teacher · state badge · enrolled/capacity — the count only for the roster audience, ADR-0012/0016), and the description as one muted sentence. The Overview and Description cards go. Sections run Sessions → Announcements → Students → Sent messages → Volunteers → Certificates and render only with content or an action: Announcements hides when it has no posts and the viewer cannot post, and a poster gets a **Post** button instead of an always-open compose box; Sent messages is a compact card after the roster, hidden until the Course has a message ("Message the class" stays in the header); Volunteers hides when none are assigned; Certificates keeps its previews at a glance size, or one quiet line before the close. Session groups are ruled lists, and the page carries one primary Mark — today's Session, else the oldest overdue one while the Term runs (the ADR-0050 rule).
- **Constant columns go, by scope token.** A teacher's `own` Courses all name them and share their one Sede (ADR-0011), so the Teacher and Campus columns and the Campus filter go; their `enrolledInOwnCourses` students hide Campus too, and a list hides its Actions column when the viewer can act on no row. The Courses list drops Program for everyone (the filter stays).
- **Copy.** List subtitles that narrated the demo and the uppercase detail-page eyebrows go (`PageHeader` loses `eyebrow`). The student browse line, the bulk-email "simulated" note, and the mark-attendance instruction stay.
- **One `SectionHeader`.** Every section on the Course, Student, Teacher, and Program detail pages and the TCU page opens with the same unboxed h2 with an optional count and action. `ListHeaderBand` and the Enrollments custom band are deleted; key-value panels (Identity, Guardian) stay Cards. Every list page shares one filter toolbar: search up to `max-w-sm`, selects beside it.

## Consequences

- Matrix cells change only in `view` (plus the tcu `tcu` cell keeping `log`); no scope token, store guard, or `STATE_KEY` changes. The matrix test pins the new cells; an App-level route test pins each cut route redirecting to the dashboard and marking staying reachable for the Course's teacher.
- Mutations are reused, so cache refresh stays the write-set invalidation (ADR-0029): deciding a request on the Enrollments page refreshes the dashboard counts, rosters, and browse seats.
- Every view that joins reads gates on all of them (ADR-0030): the request rows, the rollup, the TCU page's log heading.
- The landing's proof marquee only captions routes; every persona entry still lands on its dashboard (or the teacher's golden-path Course).
